# Security invariants

The properties AgentShield must keep whatever an input, a client, the AI provider or an operator does, with the code
that keeps each one and the evidence for it. Built from the code and its tests as of 2026-10-07 (Milestone 13). Where each control sits
in the request: [security architecture](security-architecture.md). What an attacker can touch:
[attack surface](attack-surface.md).

**Status**

| Status | Meaning |
|---|---|
| Proven | A named automated test, or an explicit code path, demonstrates the invariant as stated |
| Partially proven | Demonstrated for part of the invariant only; the row says which part is not |
| Unproven | Believed by design, not demonstrated |

"Review" below means the finding `InconclusiveAnalysis.AiAnalysisIncomplete` (Medium) is added: a deterministic Allow
becomes Review, Review stays Review, Block stays Block.

## Kinds of evidence

- **Tests** prove the behaviour their names state, for the inputs they use. Exhaustive tests (invariants 33 and 34)
  cover a whole finite space. Property tests (invariant 37) cover fixed random samples.
- **Mutation testing** (Stryker.NET, Milestone 8) checks that the tests fail when the code behind them is changed. It
  covered the code behind invariants 1, 3–13, 20–22 and 33–37: the Security project (detection, fusion, risk, policy,
  redaction, the AI stage and its validator), the capacity gate, circuit breaker and token budget, authentication and
  rate limiting. The AI project (strict parser, Gemini adapter) and the rest of the API were not in a mutation scope. Scores and the survivors that were accepted are listed in the
  [test coverage summary](test-coverage-summary.md). The activity code (invariants 39–43, Milestone 9) is in no Stryker
  scope; its key tests were checked with hand-applied mutants instead. The agent action authorization code (invariants
  44–56, Milestone 10) has five focused Stryker scopes (`tests/mutation/stryker-agent-*.json`), and the tool gateway
  (invariants 57–70, Milestone 11) its own (`tests/mutation/stryker-gateway-*.json`), as do the activity summary and the
  D-21 change (`stryker-attacklab-application.json`, Milestone 12); the Attack Lab console (invariants 71–73) was checked
  with 28 hand-applied frontend mutants. The Milestone 13 code (invariants 74–81) has four scopes
  (`tests/mutation/stryker-approval-*.json`) plus 16 backend and 12 frontend hand-applied mutants, because Stryker cannot
  compile any mutant inside `ToolGateway.ExecuteAsync`. Scores and the classification of every survivor are in the
  [test coverage summary](test-coverage-summary.md).
- **Browser checks** (`frontend/agentshield-web/e2e`) show the console's behaviour in a real browser against the real
  API. They run on demand and are not part of `dotnet test` or `npm test`.
- No code-coverage tool has been run, so no line or branch percentage is claimed.

## Summary

81 invariants: **76 proven, 5 partially proven (11, 16, 28, 29, 37), 0 unproven.** The 13 agent action invariants
(44–56) are proven as stated; their stated scope (AgentShield decides, the caller enforces; the input decision is
reported) is part of each invariant, not a partial proof. The same holds for the 14 tool gateway invariants (57–70):
they are proven for the tools behind the gateway (one), per process. Invariant 44 was amended in Milestone 11 (the
boundary still executes nothing; the gateway now does), and invariant 68 in Milestone 12 (D-21: a cancelled tool call is
recorded as failed). The three Attack Lab invariants (71–73) are proven for the console and the summary endpoint; they
add no detection or enforcement claim. The eight Milestone 13 invariants (74–81) are proven per process; invariant 78's
scope (calls that reference their input analysis) is part of the invariant. Invariants 66 and 68 were amended in
Milestone 13 (the F7 review; cancelled sinks). The partial ones are limits of
the design or of the evidence. A configuration option sends Blocks to the AI (11). Unexpected exception text is not
proven free of input (16). A sink that fails inside Serilog is undetectable (28). Hidden-text carriers other than tag
characters and variation selectors are not decoded (29). The robustness properties hold for fixed samples and
wall-clock bounds (37); the U+FFFE gap in it (D-18) is fixed.

These invariants say nothing about detection breadth. An attack the rules and the AI do not recognise is Allowed
without breaking any invariant here (deterministic recall 0.38 on the synthetic set; see the
[coverage matrix](security-coverage-matrix.md)).
